#### 从死板的优先级，到动态生成的「注意力清单」

几乎所有 PM 都有过这样的体验：周一精心梳理出一份本周优先级清单，但到了周二上午，线上报警、大客户突然提出的定制需求、紧急招聘面试就会把整张清单冲得稀烂。静态的待办事项总是在混乱的真实工作中迅速过时。

针对这个痛点，实践中摸索出的首个核心工作原语叫作**「注意力清单」（Attention List）**。

这项机制由常驻 Agent 实时跟踪你在全天工作中**实际投入的精力和注意力**，动态提炼出当前正在推进的项目焦点。注意力清单反映的是你「当前正在忙什么」，它不能等同于「应该优先做什么」，更无法替代人工手写的战略目标；它的核心作用是记录实际精力流向，以便与既定目标客观对照偏差。

```
传统工作流（容易脱节失效）：
[静态周计划 / 优先级列表]  ──(被现实打乱)──>  [疲于应付 Slack / 邮件 / 突发事故]

Grok Bot 动态工作流：
[Slack / 邮件 / 会议录音 Granola / 日历] 
      │
      ▼ (每小时静默分析实况)
[Chief of Staff (幕僚长)] ──> [动态注意力清单 (Attention List)]
      │
      ├─ 1. 反向过滤噪音：仅保留同时指名且匹配焦点的邮件，其余归档
      └─ 2. 真实精力审计：对比「口头计划」与「实际时间消耗」，找出可托管环节
```

##### 注意力清单的两种具体用法

1. **作为全天信息流的动态过滤器**：PM 每天会收到成百上千条 Slack 消息和邮件。作者给出的个人归档规则是：除非某封邮件直接指名道姓提及你、并且内容切实对应清单中的焦点项目，否则按小时归档。这个强过滤条件是他的配置示例，并非注意力清单的默认功能。在日常协同中，幕僚长 Agent 还会主动协助日历排期：例如上周它先发送日程预占（holds）并询问作者选择开始时间，在作者回复「上午 10 点（10am）」后，Agent 便自动将预占移动到对应时间。
2. **作为真实精力分配的对照镜**：注意力清单反映的是实际精力流向，每周末或每天结束时，可以将其与人工手写的战略目标客观比对并对照偏差。如果发现自己在某类琐碎事务上耗费了过多时间，立刻就能识别出后续可以剥离并委托给专职 Agent 的具体边界。

##### 按本篇工作流改写的配置示例（注意力清单）

> **提示词设定（以幕僚长 Agent 为例）：**
>
> 「建立注意力清单：请以 `[例如：每小时]` 为周期，主动检索我的邮件、Slack 关键频道、Granola 会议纪要与日历日程；为我当前实际在推进的项目提炼出一份精炼的实时项目集，写明各项目当前进展状态以及接下来需要发生的下一步动作。」
>
>
>
> **日常调取与过滤指令：**
>
> 「对照我当前的注意力清单，检查我的收件箱：将所有与当前核心焦点无关的邮件直接归档 `[保留带人工提及且相关项]`。」
>
> 「对比我本周的日历和注意力记录，列出我实际耗费时间最多、但在未来可以直接剥离并交由独立 Agent 承接的工作项。」

关键约束说明：在配置此类过滤与归档规则时，必须显式限制筛选条件，避免 Agent 误将跨部门紧急协同通知静默丢弃；同时建议在初期保留归档日志供人工抽检。
