Mistral 推出了旗舰大模型 **Mistral Large 4**（代号 ML4，团队内部戏称为“le Chonk / 大胖子”）的公众预览版 API。官方宣布计划在月底开放模型权重（目前权重尚未发布，具体许可细节也未提供），并介绍了其在欧洲自建数据中心、由 3,800 张英伟达 Grace Blackwell GPU 构筑的自主基础设施。

这款模型总参数量达到 1.05 万亿（1.05T），采用稀疏混合专家架构（MoE），在每个 Token 的计算步骤中只激活约 490 亿参数（49B）；在产品定位上，它将指令遵循、推理与多模态 Agent 能力整合于单一模型中。Mistral 将企业可控能力作为重点发布方向，聚焦在**网络安全实战、复杂代码工程、长流程 Agent 工具使用，以及金融与法律专业工作流**等对数据与运行政策有严格要求的场景。

### 架构与体量：为什么叫“大胖子”（le Chonk）？

在模型卡和官方发布中，Mistral 幽默地把 ML4 叫做“le Chonk”（网络流行语，形容圆滚滚、体量巨大的动物）。从规格上看，它确实是个庞然大物，其工程架构的设计取舍十分明确：

- **总参数 1.05 万亿，激活参数 490 亿**：它采用颗粒度更细的混合专家架构（Granular MoE）。总参数与激活参数的区别在于：总参数是整个模型的完整知识网络，部署系统仍需存储完整权重；而激活参数则是模型在每步生成单个 Token 时，由门控路由挑出参与当前浮点运算的特定专家模块。MoE 架构虽然减少了每个 Token 计算时参与运算的参数量，但服务器依然需要存储 1.05 万亿参数的庞大总权重，减少参与计算的参数，并没有让总权重变小；实际速度与部署开销还取决于硬件、精度和服务配置。
- **原生视觉编码器与 1M 上下文**：模型集成了约 16 亿参数（1.6B）的原生视觉编码器，并支持 100 万 Token 的上下文窗口（1M Context）。这两项是相互独立的规格：1M 上下文允许容纳长篇文档或多轮历史，但面对超高分辨率卫星图像或复杂机械图纸时，模型并不能仅凭单次输入自动看清所有微小细节，仍需要配合视窗缩放、局部裁切等外部工具才能完成跨层级核对。
- **多语言与欧洲自主运营**：训练数据覆盖超过 160 种语言，囊括欧盟全部官方语言。Mistral 与金融、工程制造、物流、医药等领域的企业合作训练 ML4，并使用了向客户提供的同款训练、定制与强化学习环境（Mistral Forge）。这把通用模型研发与企业按业务任务进行定制联系起来：客户使用的训练工具，也用于 Mistral 自己的旗舰模型。模型在欧洲本土由 Mistral 自建数据中心内的 3,800 张英伟达 Grace Blackwell GPU 从头训练，预览版也部署在该基础设施上；Mistral 强调其在欧洲法律管辖下提供端到端自主运营，避免依赖其他云服务商，但企业本地的独立自部署仍需等待后续权重与许可的具体开放。

### 网络安全实战：正当漏洞复现受阻，开放权重怎么解？

在网络安全运维中，防御团队经常遇到一个实际问题：要修补一个系统漏洞，往往需要先在受控环境中复现该漏洞的触发条件。然而，部分云端商业大模型设置了较严格的通用安全风控机制，在处理涉及漏洞利用特征或渗透指令的输入时，某些正当的漏洞复现与应急响应任务可能会触发服务商层面的安全策略拒绝（Safety Refusal）而无法继续。Mistral 强调，在安全事故处置中途失去某项模型能力，本身也可能成为重大安全风险：已经依赖模型推进的排查、复现与修补可能被迫停下来。自主运行的价值因此还包括应急连续性——组织可以按自己的政策安排和审计安全工作，减少对服务商临时决定的依赖。开放权重与自部署目前仍是计划，当前公众预览服务由 Mistral 托管。

- **40 道 CTF 安全竞赛（Cybench）**：在由 40 道竞赛题组成的 Cybench 测试中，ML4 解出了 93% 的题目，在公布的开放权重模型中位居前列。此外，在官方公布的内部 CTF Speedrun 演示中，包含 19 道内部安全挑战题目，ML4 完成了其中的 18 道（同场对比中 GLM-5.2 完成 16 道、Kimi K3 完成 15 道、GLM-5.3 完成 14 道、DeepSeek V4.1 Flash 完成 14 道、DeepSeek V4 Pro 完成 10 道）；这套 19 题内部演示与前述 40 题 Cybench 是不同任务集。

#### 逆向工程不是“一键神话”：56 轮轨迹交互的实操过程

在官方公布的一段对未知二进制可疑文件 `sample.bin` 进行分析的演示中，模型经历了 56 轮轨迹交互（Trajectory turns，而非单纯 56 次工具调用），展示了逐步推进的排错过程：

1. **静态特征分析**：模型首先调用工具查看文件格式、导入表和字符串列表。
2. **反编译与载荷解码**：随后对可疑代码进行反编译与字节读取，从中提取并解码出一段 892 字节的加密有效载荷（Payload）。
3. **API 哈希反查受挫**：模型尝试反查 Windows API 哈希以明确系统调用行为，但中途多次反查失败。
4. **转向规则编写与验证**：在哈希反查未果后，模型转向根据已解出的代码逻辑编写 YARA 特征检测规则；该规则编译后成功命中样本，并在给定的 683 个纯净文件测试集中确认误报率为 0。
5. **补齐证据与完成交付**：在提交最终分析报告时，后台检查系统连续三次因“结论缺少对应数据支撑”退回报告。模型通过工具返回的声明标识（Claim IDs）逐项修复报告中的证据引用，最终交付了包含 17 项已证实结论、2 项合理推断和 1 项未确认结论的 20 项主张报告。

这种在长链条中通过工具试错与纠错的能力，是安全 Agent 落地的重要前提。正当任务能够复现漏洞并不意味着模型解除了安全限制：在面对恶意攻击请求时，模型依然会执行拒绝。在 Mistral 公布的恶意网络请求拒绝评测中（综合 JailbreakBench、StrongREJECT 与 AgentHarm 三项测试），ML4 的平均拒绝率达到 95.3%；在防御间接提示词注入（Indirect Prompt Injection，指网页或文档中夹带隐藏指令诱导 Agent 偏离任务）的 Lakera B3 测试中，ML4 录得 93.3% 的攻击抵抗率，与 GLM-5.3 并列最高；在用户交互责任表现的 KORA 评测中，ML4 得分为 1.691 分（满分 2 分）。此外，官方提到的“减少安全过滤、开放扩展网络安全能力”版本，目前仅提供给审定的合作伙伴、安全机构与政府红队用于联合演练，并不代表公共 API 或未来的常规调用没有任何安全约束。

### 强化学习与训练工程：当前 3,000 卡集群上的规模化 RL

ML4 的预训练在 Mistral 位于欧洲自建数据中心的 3,800 张英伟达 Grace Blackwell GPU 上进行，当前的公共预览服务也运行在该基础设施上。而在后训练（Post-training）阶段，Mistral 投入了当前规模约 3,000 张 GPU 的集群进行大规模强化学习（RL）。

![模型在 SFT 与 RL 各阶段任务指标的演进曲线](https://best.xiaohu.ai/media/mistral-large-4/source-29.webp)

SFT 向 RL 演进趋势：官方图表示范了复杂代码 Agent 任务、代码库理解与专业交付任务从监督微调到强化学习阶段的内部指标变化。

后训练阶段的大规模强化学习机制主要包括以下几个方面：

- **大规模尝试与训练数据生成**：在由 3,000 张 GPU 组成的强化学习集群中，一组自动扩缩的执行节点（Actors）并发生成数万条探索轨迹（Rollouts，即模型在任务环境中自主尝试探索的实际解题过程），模型参数更新则异步进行。随着基座模型能力提高，传统的人工标注示例已不足以提供足够的挑战，因此需要让模型在自身尝试的结果上进行强化学习，并随能力提升不断加大任务难度。该管线每天生成约 330 亿总 Token，经过筛选和掩码处理后，提取出约 **160 亿可用于策略更新的模型生成 Token**（Trainable completion tokens）。
- **模块化可组合验证环境**：为了适应多样化的真实任务，训练环境提供了统一的可组合接口，使单次强化学习训练运行能够同时覆盖单轮对话、复杂科学问题求解、安全对齐、事实性检验以及长程工具使用等多种任务类型。这些训练环境共享了代码沙箱、网页搜索与外部 API 等脚手架；在验证反馈环节，系统根据任务类型将奖励模型、单元测试、大模型裁判和静态检查按需组合，以此评估模型尝试的成败并提供训练信号。
- **长轨迹策略稳定性**：在包含多轮工具调用与长程交互的复杂任务中，异步训练会导致生成探索轨迹时所使用的模型策略落后于后台正在更新的最新策略（即策略陈旧性与策略漂移，Staleness & Off-policy drift），这会影响长轨迹训练的稳定性。Mistral 表示其采用了跨阶段优化方法以减轻陈旧性与漂移，使得训练能够支持达数百万 Token 的探索预算（Rollout budget，这是训练阶段允许模型多次压缩后使用的探索总预算，与推理时的 1M 上下文窗口是不同概念）。
- **阶段演进与评测区分**：Mistral 表示，训练环境里的改善也迁移到了下游评测，最终能力由 SFT 与 RL 两个阶段共同贡献。三条内部下游任务曲线中，复杂代码 Agent 指标从 SFT 结束时约 58.5% 到 RL 结束时 68.84%；代码库理解从约 24% 到 38.66%（RL 初期曾回落到约 20%）；专业交付任务指标从约 1,380 到 1,511。图中未注明具体基准，不能将 1,511 当作 AA-Briefcase 的 1,393 Elo，也不能将 68.84% 当作 DeepSWE 的 61.7%。

训练奖励上涨，说明模型更会完成训练环境按规则计分的任务；下游评测改善，才进一步说明学到的策略能帮助它完成其他评估任务。两类图一起看，才能理解这套训练是否带来了环境之外的收益，而不是只在训练题里拿到更高奖励。

**模型的尝试，变成下一轮训练材料**机制示意 · 非训练架构细节

#### 2. 评估与选型考量

- **从自有任务与工具失败率进行检验**：面对涉及“文档检索、图像查验、多步骤工具调用”的长流程工作流，开发者应建立针对自身业务的验收测试，重点考察模型在面对调用失败、参数报错时的纠错韧性以及最终交付成果的可用性，以此检验模型表现。
- **自部署需等待权重与许可发布**：对于需要严格数据主权与私有化运行的企业，官方计划在月底开放模型权重。具体的许可条款、硬件要求与资源配置规范尚未披露；由于模型总参数量达到 1.05 万亿，部署时仍需完整存储庞大权重，目前无法单纯由 49B 激活参数来推估具体的服务器规格与显存门槛。
- **轻量常规任务无需盲目追大**：对于常规的文本摘要、基础对话或单文件代码补全，不应单纯依据总参数体量来判断性价比，而应综合权衡端到端延迟、多轮工具调用产生的总体 Token 成本以及实际产出质量。

### 架构与体量：为什么叫“大胖子”（le Chonk）？

在模型卡和官方发布中，Mistral 幽默地把 ML4 叫做“le Chonk”（大胖子）。从规格上看，它确实是个庞然大物，其工程架构的设计取舍十分明确：

1.05T
总参数 · 完整权重仍需存储

49B
单 Token 激活参数（细粒度路由）

3,800
欧洲本土 Grace Blackwell GPU

每步计算
激活 49B 参数降低单步运算

采用颗粒度更细的混合专家架构（Granular MoE）。在每步生成单个 Token 时，门控路由仅挑选特定专家模块参与浮点运算，减少单步参与计算的参数。

权重存储
存储 1.05T 全量权重不可减免

MoE 架构虽然减少了每个 Token 计算时参与运算的参数量，但服务器依然需要存储 1.05 万亿参数的庞大总权重，减少参与计算的参数，并没有让总权重变小；实际速度与部署开销还取决于硬件、精度和服务配置。

此外，模型集成了约 16 亿参数（1.6B）的原生视觉编码器，并支持 100 万 Token（1M）的长上下文窗口。这两项是相互独立的规格：1M 上下文允许容纳长篇文档或多轮历史，但面对超高分辨率卫星图像或复杂机械图纸时，模型并不能仅凭单次输入自动看清所有微小细节，仍需要配合视窗缩放、局部裁切等外部工具才能完成跨层级核对。

### 网络安全实战：正当漏洞复现受阻，开放权重怎么解？

在网络安全防御中，要修补系统漏洞往往必须先在受控环境中复现触发条件。然而，部分商业云端模型设置了严苛的通用风控，在处理包含攻击特征的输入时可能触发安全策略拒绝（Safety Refusal）。在 Artificial Analysis 综合测试中，Qwen3.8 出现了 63% 的安全阻断，Claude Opus 5.5 与 GPT-6 Astra 也各记录了 38% 的安全阻断；而 ML4 取得了 50% 的综合成功率，在开源漏洞复现单项（CyberGym-E2E）中拿下 82% 得分。

应急连续性

#### 应急连续性与逆向排错链路：按组织政策运行，减少临时失去工具的风险

Mistral 强调，在安全事故处置中途失去某项模型能力，本身也可能成为重大安全风险：已经依赖模型推进的排查、复现与修补可能被迫停下来。自主运行的价值因此还包括应急连续性——组织可以按自己的政策安排和审计安全工作，减少对服务商临时决定的依赖。

01
**静态特征分析**：调用工具查看可疑文件 `sample.bin` 格式、导入表与字符串列表。

02
**反编译与载荷提取**：读取可疑字节，从中反编译提取并成功解码出 892 字节的加密有效载荷（Payload）。

03
**API 哈希反查受挫**：尝试反查 Windows 系统调用行为，但中途多次反查失败。

04
**策略自主转向**：转向根据已解码逻辑编写 YARA 特征检测规则；在 683 个纯净文件测试集中确认误报率为 0。

05
**证据链对齐交付**：后台系统连续 3 次因“证据缺失”退回报告，模型通过 Claim IDs 逐项核实补齐证据，最终交付 20 项主张的正式安全报告。

        这段 56 轮轨迹交互（Trajectory turns）的官方演示展示：安全 Agent 的落地不在于“一键通关”的单次生成神话，而在于调用碰壁后自主修正路径、在证据受限时补齐闭环的工程韧性。
      

**正当复现并不等同于放任恶意：**在面对恶意攻击请求时，模型依然会严格执行拒绝。在综合 JailbreakBench、StrongREJECT 与 AgentHarm 的评测中，ML4 平均拒绝率达到 95.3%；在 Lakera B3 防间接提示词注入测试中，攻击抵抗率达到 93.3%（与 GLM-5.3 并列最高）。
    

### 专业垂直流程：将答案钉在可核对的证据上

通用大模型进入严肃生产力，不在于宽泛回答，而在于能不能胜任严谨的专业审核流程。在 Harvey 法律 Agent 基准测试中 ML4 获 15.8 分；在默克集团（Merck KGaA）跨年份财报分析演示中，模型经历 16 轮交互查出深藏于附注中的第三层级或有对价资产，核对账面价值从 2.19 亿欧元降至 1.18 亿欧元（同比变动 -46.12%），并提取出税后折现率从 6.3%–7.3% 变为 6.6%。

### 训练工程：3,000 卡集群上的规模化 RL

ML4 的预训练在欧洲自建的 3,800 张英伟达 Grace Blackwell GPU 上完成，而后训练中的强化学习（RL）当前使用规模约 3,000 张 GPU 的集群开展训练。

### 成本账本与企业选型指南

当前公众预览版标准 API 资费公布为：输入 $1.36 / 百万 Token，输出 $4.18 / 百万 Token。对于计划在实际业务中落地的技术决策者，需要把握三个核心界限：

企业选型与自部署关键考量

- **不要混淆激活与显存规格**：由于模型总参数量达到 1.05 万亿，部署时仍需完整存储庞大权重，目前无法单纯由 49B 激活参数来推估具体的服务器规格与显存门槛。
- **根据工具失败率与纠错能力验收**：多步骤长流程任务中，应在自有真实业务环境中测试模型在面对报错、沙盒超时、证据不齐时的纠错能力，并核对最终成果是否可用。
- **轻量任务无需盲目追大**：对于基础文本摘要或简单对话，应综合评估端到端延迟与多轮 Token 累计成本，再判断大模型在当前任务中的收益。
