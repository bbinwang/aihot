### 任务成本与重试成本

你并非为了购买数百万个 token 而开始工作。你的目标是构建一个功能、完成一次迁移或运行一个任务。token 数量只是模型完成任务所需的量。

两个每 token 成本相同的模型，在完成同一任务时的总成本可能相差很大。一个模型只读取一次代码。另一个模型读取代码、尝试修复、再读取一次。每一步都是一个轮次，每个轮次都会重新发送到目前为止的对话。因此，需要更多轮次的模型即使单价相同，成本也更高。

读完本文后，你应该能回答关于自己工作的三个问题：

- 在 Opus 5.5 上，我的典型任务花费多少？
- 哪些设置会改变这个成本，变化幅度是多少？
- 如何检查我自己的会话使用情况？

我想提前说明的权衡是：每一种减少 token 消耗的方法，都可能让你无法完成任务。降低努力程度、使用更小的模型或减少上下文，确实可以节省 token。但一次重试的成本远高于这些节省。本文试图为每种权衡标上价格。

这里的一些数字是标价，另一些是基于标价构建的示例。图表是可交互的，请在阅读时调整输入参数。这些是尽力而为的示例，请务必查阅我们的文档并自行计算。

### 任务成本是多少？

Claude Code 中的任务是一个循环。模型读取对话、调用工具、读取结果，然后再次循环，直到完成。每次循环都是一次请求。四个因素决定了循环的成本。

**轮次。** 每个轮次都会重新发送到目前为止的对话。轮次越少，处理的输入就越少。

**缓存读取。** 轮次重新发送的大部分内容都是模型在上一个轮次中看到的文本。这部分按缓存读取计费，价格仅为输入价格的一小部分。

**输出 token 类型。** 最昂贵的 token，价格是输入价格的五倍。[思考](https://platform.claude.com/docs/en/build-with-claude/extended-thinking)按输出计费，因此模型在得出答案过程中思考越少，成本就越低。

**模型。** 每个模型都有自己的价格，列在定价页面上。你选择的模型决定了每个 token 的价格。

我们的示例使用 Opus 5.5 API 标价：每百万输入 token 4 美元，每百万输出 token 20 美元，每百万缓存读取 0.20 美元。与后面的计算器一样，示例将缓存的输入按读取价格计费，其余按输入价格计费，并忽略缓存写入。token 数量仅为示例。

#### 轮次

假设一个任务开始时包含 20K token 的上下文，随着模型读取文件和工具结果，上下文增长到 120K。在 40 个轮次的情况下，平均每个轮次发送约 70K token。这意味着该任务总共处理约 2.8M 输入 token，尽管对话从未超过 120K。假设 90% 来自缓存，输入成本约为 1.62 美元。同样的任务在 25 个轮次中处理约 1.75M token，输入成本约为 1.02 美元。

一个轮次的成本不仅包括它新增的 token，还包括重新发送之前所有内容的成本。因此，最便宜的轮次是你不需要的那个。

一种可以减少轮次的习惯是给模型提供检查自己工作的方法。例如，一个可以运行的测试、一次构建或一个调用端点的脚本。能够自我检查的模型会更早发现自己的错误。

一个能一次性收集所需信息并批量调用工具的模型，也能减少重新发送的次数。

#### 缓存读取

同样的 2.8M 输入 token，如果完全不来自缓存，成本为 11.20 美元。在 90% 命中率下，成本为 1.62 美元；在 96% 命中率下，约为 0.99 美元。没有其他设置能如此显著地影响输入成本。稳定的会话本身就能保持高命中率。我将在本文后面介绍一些避免破坏缓存的操作。

#### 输出 token

在 Opus 5.5 上，一个输出 token 的成本是缓存读取的 100 倍。一个典型任务的 60K 输出 token 成本为 1.20 美元，相当于从缓存中读取 6M token 的成本。输出包括思考。你需要为所有输出付费，即使 Claude Code 只向你显示摘要。这就是为什么努力程度（主要改变模型思考量）会如此显著地影响账单。

#### 模型

缓存读取更便宜的模型主要有利于长会话。输出更便宜的模型则主要有利于需要大量推理的任务。

### OPUS 5.5 的变化

有两项变化：价格，以及模型完成的工作量。

**每条价格线都降低了。** 输入和输出 token 比 Opus 5 便宜 20%。缓存读取便宜 60%。输入价格下降，读取费率也随之下降，从输入价格的十分之一降至二十分之一。图 A 比较了每百万 token 的两种模型。这些是 API 标价。在 Pro、Max 或 Team 方案中，Opus 5.5 的较低价格会传导至你的限额（包括缓存上下文），因此相比 Opus 5，你的限额大约能多使用 25%。缓存读取的额外降价是 API 价格变化。

另外，Pro、Max、Team 和基于座位的 Enterprise 方案的五小时限额提高了，符合条件的订阅用户可获得一次限额重置，可在自行选择的时间使用。你可以在网页端或 Claude Desktop 的“设置 > 用量”中找到该重置选项，而不是在你终端中的 Claude Code 里。重置适用于你的整个账户，包括 Claude Code。

### 最大化会话价值的技巧

Opus 5.5 更低的价格使每个 token 的成本降低。你运行会话的方式决定了你会使用多少 token，以下步骤会有所帮助。

#### 在更换模型之前提高 effort

Effort 设定了模型在每个轮次上花费 token 的总体倾向：其思考、书写的文本以及工具调用。在较低的 effort 下，它会进行更少的工具调用并保持更简短。Opus 5.5 有四个级别（low、medium、high 和 xhigh），加上单个会话的 max。在下方选择一个级别，查看何时使用它以及设置它的命令。

Medium: 适用于范围明确的日常工作范围清晰的日常工作。每个轮次的思考少于 high，因此每个轮次成本更低。当任务范围明确时，从这里开始。

- `/effort medium`
- `/effort status`
- `/model`
- `/usage`

级别从每个轮次最少的思考到最多的思考。

Claude Code 为每个模型设置默认级别，`/effort status` 会显示你的当前级别。对于明确范围的日常工作，尝试 **medium**。当 medium 停滞不前时，尝试 **high**。它每个轮次的花费比 medium 多，但比换用更大的模型少。对于机械性工作（如重命名或跨文件应用已知模式），使用 **low**。

在 Opus 5.5 上，默认是 medium，比 Opus 5 的默认 high 低一个级别。不同模型上相同级别的思考量并不相同。在给定级别，Opus 5.5 每个轮次的思考量多于 Opus 5，尤其是在 xhigh 和 max 时。因此不要沿用你为 Opus 5 选择的级别。从 medium 开始，并将 xhigh 和 max 保留给你已测量到收益的工作。

关于 effort 定价的粗略理解：假设 high 在整个任务中增加了 20K 思考 token。在 Opus 5.5 上，这相当于 $0.40。一个包含十轮次、100K 缓存上下文、总共 10K 输出 token 的重试循环，成本大致相同。因此，在一个能节省一次重试的任务上，high 就能回本。而对于 medium 首次就能完成的任务，它就浪费了。

##### 当 medium 只修复一层时

你需要更高 effort 的最明显标志是修复只停留在某一层。

假设一个 API 处理程序中的字段被重命名。在 medium 下，模型更新了处理程序，该处理程序的测试通过了，但客户端仍然发送旧字段。它做了被要求的事情，只是没有读得足够远以找到第二个调用者。在 high 下，在编写之前它会花费更多轮次读取调用点，并同时更改两层。

一次检查也能抓住同样的 bug。如果模型能运行一个经过客户端(client)的测试,旧字段会在它被写入的那一轮、以 medium 努力度,在该测试中失败。所以在提高努力度之前,先检查模型是否有办法检查自己的工作。一次测试运行消耗一轮及其输出。更高的努力度会给每一轮增加思考量。

如果提高努力度等级和添加检查都不起作用,那就切换到更大的模型。

##### 在会话中途更改努力度

在 Claude Code 中,运行 /effort 并带上一个等级,例如 /effort high。/effort status 会打印当前等级。你可以在任务中途更改它,新等级将应用于下一个请求。

在 Opus 5.5 上,使用 API 密钥或 Claude 订阅时,更改努力度会保留缓存(cache)。你可以为某一个困难步骤提高它,然后再降低,而无需重写对话。在 Amazon Bedrock、Google Cloud 的 Agent Platform 或 Claude apps 网关上,更改努力度仍然会清除缓存的对话,下一个请求需要为全部内容支付缓存写入(cache-write)价格。Opus 5.5 的思考(Thinking)功能始终开启,因此没有思考设置需要更改。

#### 为你的工作选择合适的模型

模型选择决定了会话中每个 token 的价格,因此它对账单的影响比努力度更大。它的影响范围也更广。每个继承主模型的子代理(subagent)也会继承其价格。大多数工作日需要三种模型:一个小的用于查找,Opus 5.5 用于你密切监督的工作,一个更大的用于最困难的任务。

##### Opus 5.5 作为日常主力

将 Opus 5.5 用于你监督的工作:跨几个文件的功能开发、调试,以及带后续修改的代码审查。你会阅读它的产出,并在它偏离方向时介入,因此反馈循环保持短促。

##### 升级到 Fable 5.1

**当结果比 token 价格更重要时,升级到 Fable 5.1。** 例如你不会监督的长时运行、代码库中没有现有模式的问题,以及协调多个子代理的大型变更。不要等到第三次失败。如果处于 xhigh 的 Opus 5.5 两次遇到同一个问题,就切换,问题解决后再切回来。对于交互式工作,Opus 5.5 更合适,因为它的延迟更低、成本也更低。

Fable 5.1 的标价为每百万输入 token 10 美元、每百万输出 token 50 美元,是 Opus 5.5 价格的两倍半。其缓存读取成本为每百万 token 0.25 美元,仅为 Opus 5.5 费率的 1.25 倍,因为它们的计费标准是其输入价格的 0.025 倍。因此,在长时、缓存密集的运行中这个差距最小,而在写入量大的任务上差距最大。

在自然断点处切换。缓存属于之前的模型,因此新模型的第一个回合需要为整个对话支付写入价格。先运行 /compact,或用一个简短的书面计划开启新会话,以减小那个回合的规模。运行 [/model](https://code.claude.com/docs/en/model-config) 并带上别名或模型名称即可切换。/model 还会将你的选择保存为新会话的默认值,因此在困难部分完成后记得切回来。

##### 降级用于查找

**降级到 Sonnet 或 Haiku 用于查找,而不是用于编写代码:** 搜索和总结的子代理、阅读日志和测试输出,以及"这个定义在哪里"之类的问题。对于跨多个文件的机械性编辑,请保留 Opus 5.5 并将努力度设为 low。编辑工作保持在编写其余代码的模型上,每轮成本更低。

要将[子代理](https://code.claude.com/docs/en/sub-agents)放到更小的模型上,在其定义中设置 model: haiku 或 model: sonnet。要将所有子代理放到同一个模型上,设置 CLAUDE_CODE_SUBAGENT_MODEL 环境变量。子代理定义中指定的模型会覆盖该变量。未设置模型配置的子代理将在你的主模型上运行,除非设置了该变量。

每个子智能体在自己的上下文窗口中运行并返回摘要，因此它的文件读取不会污染你的主对话。它仍然需要为自己的 token 付费，因此模型设置决定了这项开销的成本。

Agent团队（实验性功能）会放大这一点。每个团队成员都是一个独立的 Claude Code 实例，拥有自己的上下文窗口，并且会持续消耗 token 直到退出。我们的[成本文档](https://code.claude.com/docs/en/costs)指出，当团队成员在计划模式下运行时，一个团队大约消耗标准会话 token 量的七倍。请保持团队规模小巧，确保每个任务独立自洽，并在成员完成其部分后将其关闭。

其中的权衡：如果一个小模型误读了一个搜索结果，会导致主模型去查找错误的文件，而主模型会为这次绕路买单。请将小模型用于那些错误容易被发现的工作，例如查找文件、运行测试和读取日志。

将判断性决策保留给主模型。`opusplan` 别名以不同的方式分配工作：Opus 在计划模式下制定计划，而 Sonnet 执行计划。这将代码编辑任务交给了 Sonnet，与上述建议相反。在将其设为默认配置之前，请先在自己的任务上对其进行衡量。

#### 迁移时检查你的提示词

为旧模型编写的指令可能会让 Opus 5.5 写出更多内容并重复工具调用。在 Claude Code 中运行 `/claude-api prompt-audit` 来检查你的 Claude Code 配置（例如你的技能和 `CLAUDE.md` 文件），查找这些[提示词反模式](https://claude.com/blog/reducing-cost-and-improving-performance-with-claude-platform)。它还会检查你在 Claude Platform 上构建的应用的代码。

我们在一次从 Opus 4.8 到 Opus 5.5 的迁移上测试了这一点，使用了一个包含 44 个工单的内部客户支持基准测试，其提示词包含上述几种模式。切换到 Opus 5.5（工作量不大）使基准测试的成本降低了约 18%。运行 prompt-audit 后进一步降低了 9%，总成本比 Opus 4.8 的起点低约 25%。审核移除了那些导致模型写出更多内容并重复工具调用的仪式化指令：一个强制性的六步流程、一个草稿纸规则、一个双重验证规则，以及相互矛盾的指令。

这个结果来自一个基准测试，因此请将其视为一个示例，而非期望达到的数值。先运行审核，然后在真实任务上比较执行前后 `/usage` 的数据（请参考“自行衡量”部分）。

#### 缓存与压缩

Claude Code 会为你处理缓存和压缩。你运行会话的方式决定了它们能节省多少资源。

##### 缓存的工作原理

Claude Code 会缓存请求中重复的部分，例如系统提示词、工具定义以及当前对话内容。

在 Opus 5.5 上，读取缓存内容的成本是新鲜输入 token 成本的 5%。写入缓存的成本高于读取新鲜内容，按当前价格计算，五分钟缓存的写入价格为输入价格的 1.25 倍，一小时缓存的写入价格为输入价格的 2 倍。每次命中缓存都会免费重置其生命周期。

在 Claude Code 中，缓存生命周期取决于你的付费方式。使用 Claude 订阅时为 1 小时。使用 API 密钥或云服务商时默认是 5 分钟，而一旦订阅开始消耗使用额度，也会降为 5 分钟。

在上下文大小为 120K token 时，Opus 5.5 上一次五分钟的缓存写入成本约为 $0.60，一次读取成本约为 $0.02。一次写入的价格等于 25 次读取。使用 API 密钥时，一次六分钟的咖啡休息就会将下一次 $0.02 的读取变成 $0.60 的写入。同样大小下，一小时的缓存写入成本约为 $0.96，并且通过 API，你可以支付这个溢价来覆盖你工作中的间隙时间。

##### 会话形状与命中率

缓存存储的是内容前缀，因此它只能重用请求中与上一个请求从头开始匹配的部分。

一个稳定的会话会在每次交互时将新内容附加到对话末尾，从而保持高命中率。任何改变请求早期部分的操作都会降低命中率。更改工具定义会清空整个缓存，而更改系统提示词会清空从更改点之后的所有内容，这几乎就是全部内容。

实践中，预期在以下情况下会发生缓存写入：

- 你暂停的时间超过了缓存生命周期；
- 你在 Amazon Bedrock、Google Cloud's Agent Platform 或网关上更改了 effort 级别（因为该级别是缓存匹配的一部分）；
- 你在对话中首次开启快速模式，这会改变缓存匹配的一部分内容；
- 你连接或断开了 MCP 服务器，这可能会改变每次请求开始时加载的内容；
- 你切换了模型，因为新模型从空缓存开始；以及
- 会话被压缩，这会重写缓存所匹配的历史记录。

所以，在会话开始时设置好这些，并在其运行期间不要改动。

##### 为什么长会话每轮成本更高

每一轮都会重新发送整个上下文，因此即使有热缓存，随着上下文增长，每轮的成本也会增加。在 Opus 5.5 上，20K token 的上下文每轮缓存读取成本约为 $0.004。在 150K 时约为 $0.03，以该大小运行 30 轮仅读取就要花费 $0.90。同样的 30 轮在 20K 时成本约为 $0.12。在 Claude 4.6 及更高版本模型中，更大的上下文窗口不会改变每 token 的价格，因此成本完全来自重新发送对话。

这些上下文中有很多是先前工作留下的：一小时前的堆栈跟踪、已处理完的文件、你后来修复的测试运行的输出。这些内容仍然会在每一轮中被发送。

##### 压缩、/compact 和 /clear

当会话接近其上下文限制时，Claude Code 会对较早的历史进行摘要，以便后续轮次发送更少内容。运行 /autocompact 并附上 token 数量，可以改变触发该操作时的上下文填充度。

有两个命令可以让你手动完成此操作。/clear 会清空对话且不产生成本，因此在切换到无关工作时使用它。/compact 保持连续性且仅花费一次请求。它会读取将要摘要的对话，并且你可以指定要保留的内容，例如 /compact keep the failing test names and the schema change.

在 150K token 时进行压缩的大致价格约为 $0.25。这包括读取、几千个输出 token 的摘要，以及在更短上下文上的新缓存写入。之后每轮在读取上节省约 $0.025，因此压缩在大约十轮内即可收回成本。在即将完成前进行压缩，其成本会高于节省的费用。

该价格假设缓存是热的。当缓存处于热状态时，摘要请求会从中读取对话，因此应在休息前压缩，而不是休息后。如果休息时间超过缓存生命周期，同样的 /compact 会重新读取整个对话并将其写回缓存。在五分钟缓存的 150K token 情况下，仅输入就约为 $0.75。如果你已经走到一条想要放弃的路径，改用 /rewind 回到较早的轮次。当缓存是热的时，它会返回一个已经缓存的此前缀。

摘要也会丢失细节。在调试会话中途进行压缩，可能会丢失关键的那一行日志。在自然的间断点压缩，并且当下一步依赖于某些具体内容时，请在 /compact 指令中说明。

##### 在输入前加载了什么

你的 [CLAUDE.md 文件](https://code.claude.com/docs/en/memory) 会在每个会话开始时加载到上下文中，因此其中的每一行都是每一轮重新发送内容的一部分。[成本文档](https://code.claude.com/docs/en/costs) 建议将其保持在 200 行以内。MCP 工具定义是延迟加载的。开始时只加载工具名称和服务器指令，完整定义会在使用该工具时加载。运行 /mcp 查看哪些服务器已连接，并关闭你未在使用的服务器。

### 自行测量

本文中的数字仅为示意。你的代码库、提示词和使用习惯各不相同，因此请针对自己的任务测量成本。以下是检查方法。

1. **在会话中运行 [/usage](https://code.claude.com/docs/en/costs)。** /cost 功能相同。会话块会显示 token 用量以及按标价估算的美元成本。提示缓存行会显示输入中有多少来自缓存。在 Pro、Max、Team 或 Enterprise 套餐中，同一屏幕还会显示你的套餐用量条。美元金额是在你的机器上按标价计算的，因此在订阅套餐中，它只是你工作量的参考，而非账单。
2. **对同一任务运行两次。** Opus 5.5 需要 Claude Code v2.1.280 或更高版本，因此请先运行 `claude update`。从你的待办事项中挑选一个任务，不要用玩具示例。使用 /model 在 Opus 5 和 Opus 5.5 之间切换。记录每次运行的轮次、输出 token 和成本。在得出结论之前，先做三到四个任务。
3. **对于团队，请使用用量和成本报告。** [Claude Code Analytics API](https://platform.claude.com/docs/en/manage-claude/claude-code-analytics-api) 提供每位用户的估算成本。[Usage and Cost API](https://platform.claude.com/docs/en/manage-claude/usage-cost-api) 按模型以及缓存与非缓存 token 细分支出。
4. **尝试努力阶梯。** 对一项困难任务分别使用 medium 和 high 运行一次。对一项机械性任务使用 low 运行一次。

#### 解读会话

在任务结束时，通过 /usage 检查三件事。

- **缓存占比。** 对于长会话，该值应该很高。如果很低，请检查是否存在长时间暂停、模型切换、中途连接的 MCP 服务器，或者在云提供商或网关上更改了努力级别。提示缓存行通常会指出最近一次缓存未命中的可能原因。
- **输出与输入之比。** 对于一个小改动却产生大量输出，通常意味着努力级别对该任务过高，或者模型正在重试。
- **总输入与对话大小之比。** 如果总输入是对话大小的许多倍，说明会话经历了大量轮次，值得阅读对话以找出循环重复的位置。

作为基准，Claude Code 成本文档给出的企业部署平均值约为每位开发者每个活跃日 13 美元，90% 的用户每个活跃日低于 30 美元。如果某个会话的成本远高于你的正常水平，则值得审查。

### 请记住

- 对于范围明确的日常工作，使用 medium 努力级别。
- 给模型提供检查自身工作的方式，并在 plan 模式下启动跨文件的更改。
- 当 medium 卡住时，将努力级别提高到 high。使用 API 密钥或订阅时，更改会保留你的缓存。在云提供商或网关上，请在中断时更改。
- 如果 xhigh 两次遇到相同问题，请切换到 Fable 5.1。问题解决后再切换回来。
- 将搜索和日志读取子代理放在 Sonnet 或 Haiku 上。将代码编辑保留在 Opus 5.5 上。
- 保持长会话持续进行，以便其缓存保持温暖。
- 在不相关的任务之间使用 /clear，在中断时使用 /compact 并附上要保留的内容的说明。
- **最重要的一点：** 在每个模型上运行一个真实任务，并比较 /usage 报告的结果。你自己的数字才是值得信赖的。
