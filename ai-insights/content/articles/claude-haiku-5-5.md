一个 AI 应用每天要做大量摘要、查找和分类时，模型每次回答的费用与等待时间都会累积。开发者要同时考虑：模型能不能把这件事做好，以及能不能长期大量调用。

Anthropic 发布了轻量级模型 **Claude Haiku 5.5**：平均运行成本比 Haiku 4.5 低约 75%，编码、电脑操作和知识工作能力也有明显提升。它是 Claude 家族在标准速度下最快的模型。（开启 Fast Mode 的 Opus 更快。）

它的主要功能与特点，可以先看这六项：

- **成本更低**：官方测算，平均运行成本比 Haiku 4.5 下降约 75%，适合需要大量调用的应用。
- **响应更快**：在 Claude 家族的标准速度模式下最快，面向实时客服、浏览器操作等对等待时间敏感的任务。
- **任务能力提升**：在官方公布的编码、电脑操作与知识工作评测中，比 Haiku 4.5 有明显进步。
- **思考投入可调**：首次在 Haiku 系列中支持 effort 设置，简单任务少投入，难任务可增加推理投入。
- **擅长高频重复工作**：面向摘要、上下文压缩、数据库查询和分类等目标明确的任务。
- **可作为子 Agent 协作**：与 Opus 5.5、Sonnet 5.5 搭配，由大模型负责复杂工作，Haiku 接手具体的小环节。

### 短请求价格降到一折，大量调用更划算

### 大模型做整项工作，Haiku 接手具体环节

一项完整任务常常包含许多小环节。通过 [多 Agent 协作](https://best.xiaohu.ai/article/specialized-ai-god-model/)，大模型可以把查找、提取、摘要等工作交给 Haiku 子 Agent （由主 Agent 调用、执行具体任务的辅助 Agent），降低这些环节的费用和等待时间。

官方博客收录的客户早期测试，展示了几种具体用法：

- 金融演示文稿辅助（Rogo）：在制作演示文稿（deck）时，由更大的模型负责整体文稿构建，Haiku 5.5 作为子代理（subagent）从 10-K 年报（美国上市公司向监管机构提交的年度报告）中提取所需的特定分部营收（segment revenue）行。其准确度足以承担该定向任务，且速度快、成本低，适合高频调用。
- 自主编程协同（Cognition / Devin Fusion）：在 Devin Fusion 架构中，Haiku 5.5 作为僚机（sidekick）配合主导模型 Opus 5.5。这套组合在 FrontierCode 评测中保持了 66.2 的测试得分，同时降低了调用成本与延迟。已可在 Devin CLI 中尝试以 Opus 5.5 为主导、Haiku 5.5 为辅助的组合。
- 企业协同与任务分流（Asana）：在其 AI Teammates 评测中，Haiku 5.5 被用于工单分类、项目初始化以及识别高风险与逾期任务。测试显示端到端任务完成延迟降低超过 30%，单个 Agent 轮次的推理速度提升最高达 2.5 倍。
- 高并发文档问答（AlphaSense）：其生产环境中“文档提问”（Ask in Document）业务每周处理约 800 万次调用，用于回答基于单篇或少数文档的具体问题。在针对 400 条查询的测试中，Haiku 5.5 的测试得分由 Haiku 4.5 的 0.76 提升至 0.84，具有统计学显著改善。
- CRM 数据审计（HubSpot）（CRM 是客户关系管理系统）：在模拟 CRM 任务评测中，Haiku 5.5 在三次运行中取得了 92.8% 的平均测试得分；在其中一项识别陈旧且模糊记录的 CRM 审计任务中，Haiku 5.5 在所测试模型中完成速度最快，且误报率最低、命中率最高。
- 企业级文档分析（Box）：在早期测试中，Haiku 5.5 相比 Haiku 4.5 得分高出 11 分，延迟约为一半；Box 计划将其用于成本报告、财务摘要及每周复盘等大规模分析任务。

### 哪些工作适合交给 Haiku？

- **重复做摘要和压缩上下文**：在长工作流中整理前面的信息，为后续步骤准备简短背景。
- **定向查询、提取和分类**：从文档中找一项数据，处理数据库查询，给工单或记录归类。
- **需要快速回应的交互**：实时客服、浏览器操作，以及主 Agent 派发的具体子任务。

这些工作目标明确、调用频繁，单次成本和响应时间的改善最容易积累成实际收益。

### 使用时还有哪些安全限制和配套变化？

安全策略也随模型能力更新：

- 价值对齐：Anthropic 报告称，在几乎所有内部对齐评测中，Haiku 5.5 相较 Haiku 4.5 均有显著改善，表现出更少的偏离预期要求的行为，协助滥用请求的意愿也更低。
