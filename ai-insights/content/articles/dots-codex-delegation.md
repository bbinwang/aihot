OpenAI 开发者体验团队的 Dominik Kundel 已经花了不少功夫配置 Codex：用记忆记录偏好，装插件，设自动化，还专门开了一个“参谋长”线程统筹工作。可他用了一段时间 Dots 后，发现最明显的变化是自己不必再记着每一个跟进步骤。

**会写代码，不等于替你记住后续的每件事。** 作者过去的流程是：

把 Appshot（应用画面快照）或 Slack 消息链接带给 Codex，让它实现功能，并交代它监控部署状态以及回到 Slack 回复结果；但每遇到一项新需求，都必须单独要求它设置自动化来跟进功能或发布计划的变动，每件事都要重复设置一次。

真正的负担在于：每项新工作都要自己组织指令、额外配置跟进方式。

现在，作者可以直接在同一个 Slack 线程里 @自己的 Dot。Chopper 接下任务、处理问题，再回到原线程回复结果，还会留意与发布有关的变化并提醒他。这让交办、执行、回报和后续跟进接在一起，作者不必每来一项新工作，就亲自拼好这套流程。

而 Dots 的出现，正是为了接管这层组织与跟进的负担。它不是要取代 Codex，而是基于同一套开源 Codex Agent 执行框架（harness，也就是让模型调用工具、推进任务的运行系统），负责接住任务并持续跟进。

这也解释了为什么已经配好 Codex 的人仍能用上它：Dot 可以沿用账号中已连接的 ChatGPT / Codex 插件，借助这些插件查询资料、在原有工具和服务中开展工作，也能利用已有的相关上下文。你不用为了增加一个交办入口，把之前的配置全部重做。

### Dot 是一个可以持续交办工作的个人 Agent

简单来说，Dot 是由 GPT-6 Astra 模型驱动的常驻专属助理。作者写作时，只能创建一个 Dot，你可以给它自定义名字、专属外观，甚至可以用你家宠物的照片作为形象。

例如 Dominik Kundel 就给自己的 Dot 起名叫 **Chopper**，并为它定制了一套顶着黑色小帽的橙色小兽形象。

[视频/音频](https://best.xiaohu.ai/media/dots-codex-delegation/source-01.mp4)

作者为自己的 Dot 设定的个性化形象「Chopper」（16 秒，无音轨），展示个性化外观与“查看改动”“运行测试”等状态标签。

Dot 的特点在于**常驻与跨端协同**。它拥有专属 Handle（比如 `@tibo-alfred` 或 `@yourname-dot`），你可以直接向它派发任务，而无需在开始前先挑选具体的 Codex 线程。
