### 他觉得现在哪里出了问题

开场，Diogo 抛了一句带脏字的反问：自动化到底都去哪了？他的意思是，AI 聪明得离谱，可除了聊天和编程，它在别的事上几乎没帮上忙。他特意说明自己不是在黑聊天机器人和编程 Agent，这两样他自己也爱用。在他眼里，手里有一大堆璞玉，却没打磨到能干活，这很“惨”。

对话里给了几个具体的画面。

**企业内部。** 一位主持人说，OpenAI 从 2020 年就在尝试自动化客服，可现在企业内部被自动化的东西非常少，项目也没做成，编程是唯一的例外。

**客服的“95%”。** Diogo 讲了自己在这波生成式 AI 之前研究客服的经历：有家公司说，自己回答了 95% 的帮助台来电，他觉得这也太高了，一看数据，几乎都是重置密码。如果按问题的独特程度算，真正被解决的大概只有 50%。他的结论是，只要面对的是人和自然的系统，后面总拖着一条很长的例外长尾。

**烦人的杂事。** 一位主持人讲了个小故事：他们成长基金的负责人 David George 试了一个新工具（转写里听起来是 Muse），用它做的第一件事，是终于退订了纽约时报。主持人说，这只是冰山一角，这类“做起来很烦人”的事都需要自动化。

**“扩散慢”不是理由。** 有人拿新技术普及需要时间来解释为什么没自动化，Diogo 说自己完全不信：AI 的潜力这么大，自动化的经济动力也这么大。

他在 Latent Space 的专访里说得更狠：如果模型真能做世界上大部分有经济价值的工作，就该回答一个问题，为什么它能解数学难题，却几乎完成不了经济上有价值的工作。他的判断是，各家模型在这件事上大约都还是零，即使已经开始了，也不到 1%；等它真发生时，会体现在经济统计里。

### 他的诊断：你优化什么，就得到什么

**他自己的转折。** Diogo 在访谈里讲了自己是怎么想明白的。2021 年底，他对 RLHF（用人类反馈训练模型）的泛化能力大为惊讶，团队还专门做实验想证伪它是不是在“作弊”，比如问“为什么冥想前要吃袜子”这类网上查不到的问题，看它能不能编出合理的回答。他说自己当时是“重能力派”，一度真觉得那个模型有机会成为 AGI，结果发现不是，世界观瞬间崩塌。官方博客里他写得更直接：他在 OpenAI 参与做出了让语言模型学会听指令、和人聊天的方法，这些成了 ChatGPT 背后的研究；那时他以为聊天模型可能通向 AGI，但很快发现“缺了非常大的一块”。（Latent Space 的导读说他是 InstructGPT 论文的合著者。）

**他的判断：裁判被优化了，任务没有。** 他对 AGI 的看法更务实：OpenAI 定义的 AGI，也就是自动化世上多数有经济价值的工作，他认为是非常可行的，因为很多工作机械简单，能外包出去的工作，本来就得有普通人能照做的简单指令，据他所见，这种程度的智能在模型里早就有了。他的“心结”就是这为什么还没落地。他给的解释是，RLHF 之后，行业分化成了“夸下海口、兑现不足”：模型好不好由人来评，所以看起来很好，被优化的是裁判，而不是自动化本身。他把“能不能自动化那些明摆着该自动化的事”比作煤矿里的金丝雀：数学被“解决”了，两年前防谷歌搜索的问答基准 GPQA 也被解决了，可汽车得来速点餐还是搞不定。

**在专访里，他把这个想法说成一个公式：训练时用什么当目标，模型就会长成什么样。** 三种主流的训练方式，目标各不相同（下表综合官方博客和专访里他的说法，最后一行是专访导读的概括）：

|  | RLHF | RLVR | RLCD（Jev） |
| --- | --- | --- | --- |
| 优化什么 | 让人类评分者满意 | 能被程序验证的结果 | 有“诚实概率”的决策 |
| 擅长 | 聊天、写作 | 数学、内核优化 | 软件能直接用的判断 |
| 代价 | 迎合、失去校准，一直需要人在回路 | 智能参差不齐，和其它软件不好集成 | 放弃自由文本，能力更窄 |

RLVR 指用可验证的奖励训练，RLCD 是他们自己提出的训练方法，意思是“面向校准决策的强化学习”，专访导读说这项技术还没公开发表。他说，RLVR 让模型的“系统 2”（慢思考）做出了惊人的成绩，但这种能力很脆、很“锯齿”，而预训练出来的模型，本质上是“系统 1”（快直觉）的思考者。

**为什么聊天训练会伤害可靠性。** 他在专访里给了一个技术解释，讲得比较绕，大意是：字符串生成有个反直觉的事实。一篇很长的文字，越长越可能出错，这在数学上看起来显然，但在实际里不成立。原因是，为了在很长的文字里不出错，模型必须变得极度保守，而这种保守会破坏概率的“校准”（模型说自己有多大把握，和它实际有多准是否对得上）；他把这叫模式坍缩，也就是模型只输出最常见的几种答案。他的结论是，拿字符串模型来做决策是“糟糕的一件事”。这是他的观点，专访里没有给出实验数据。

**他对“失控”的看法。** 访谈里他还说，自己出于一些细微的原因，当时和现在都不认为我们走在 RSI（通常指 AI 递归式自我改进）的路上；早期 OpenAI 里，人们形容 AGI 是“Ilya 加每一个 if 语句”，这个说法是有意含糊的，帐篷搭得很大，谁都能进来。

一位主持人提出了一个反驳：会不会是现实世界的数据是重尾的、有大量例外，而 AI 主要在数学、代码这类低维的世界里训练？Diogo 不完全认同“缺数据”这个解释。长尾当然存在，但他说，在金丝雀这个语境里，并不需要自动化整条长尾，凡事要务实，做可靠的软件本来就是投资。

### Jev 到底是什么

拿访谈里提到的“分析邮件”来想象：软件读到一封客户来信，要判断它该走哪条处理流程。过去要么写一堆规则，要么请机器学习团队训练一个专用模型。用 Jev，思路是让开发者直接用自然语言说明每条流程是干什么的，让它在里面挑。Diogo 说，这类能力包括分析日志、分析邮件、提供界面、和人对话。

官方博客给的一句话定义是：Jev 是“前沿智能的函数调用”，也就是非结构化的状态进去，类型化的概率决策出来。它属于官方所说的“System One 模型”（名字取自卡尼曼《思考，快与慢》里的“系统 1”，快速、直觉的那一套）。和普通语言模型比，官方强调三点不同：

- **一次并行给出全部答案**，不是一个 token 一个 token 地往后写；
- **输出是类型化的值**，选项和结构由开发者提前定义，模型不会输出结构以外的东西；
- **每个答案都带校准过的概率和置信度**，置信度高的应该更准。

对机制，a16z 的一位主持人给了个概括：把它想成一个库，你用自然语言描述想要什么，再给它一个状态机（一组状态，加上状态之间怎么跳转的规则），它就会带着一定的置信度，选择该怎么做。主持人说，这种“带置信度的选择”是软件以前没有过的东西。Diogo 没有反对，还补充了几点：

- Jev 从技术上讲，“绝对是个分类器”。他不觉得这是贬低，分类器生来就是为了有用。
- 他们的入职第一天就会画一张韦恩图：一边是 AI 擅长的，一边是代码里有价值的，Jev 就站在中间。所以它不输出外推出来的浮点数，因为 AI 不擅长这个；但概率并不新鲜。
- 他猜 Jev 可能比 2019 年一个机器学习工程团队做得还好：那时好的团队不多，得挑一个窄场景，自己收集数据集、做评测；现在你可以现场用自然语言“编程”。
- 接口把输入叫“状态”，他说是有意为之。

下面这个小演示把“状态机加置信度”摆在一起：选一封来信，看软件会把它交给哪个状态、把握有多大，再自己调一个“多有把握才放手”的门槛。演示里的信件和数值都是示意，不是 Jev 的真实输出。

主持人还追问：这是一条滑杆，一头是语言进、语言出，一头是传统的命令式程序，还是设计空间里的一个点？Diogo 的答案是滑杆。他说自己设计时的“北极星”是每美元智能，同时承认短期内每秒智能可能更有价值。官方博客给的速度和价格是：响应约 70 到 500 毫秒，输入每百万 token 0.042 美元，输出免费。主页上写的“快 193.6 倍、便宜 444.6 倍”，官方自己注明是偏高端的情形，后面会讲这些数字是怎么测的。

名字方面，官方博客说，Jev 取自经济学家 William Stanley Jevons：蒸汽机效率提高后，煤炭的需求反而增加了，同理，智能的成本每降一个数量级，就会解锁数量级更多的用例。访谈里 Diogo 也顺带说过，这些事变得可做之后，人们会创造出新的工作。

发布之后的反应也出乎他意料。他说，他认识的每个开发者都打电话来，说这东西好用、速度快；每小时都有人告诉他“我在用 Jev 做一个我完全没想到的新场景”。他觉得没人能预料到“给开发者用的 ChatGPT”，连非开发者朋友也在推特上玩梗。

### 和 Claude Code、Codex 有什么不一样

这是多数人最想问的：我们已经有 Claude Code 和 Codex 了，还要它干嘛？

Diogo 先承认这两样很好，还转述了别人的一个说法，叫“即时软件”（转写里的人名是 Gary Tannenbaum，可能有误）：它们能现场造软件，用自然语言编程，表达力和软件一样强。但他想要的是“智能软件”：不是去自动化软件工程，而是扩展软件本身能做的事，让本该能自动化的东西真的能自动化。

一位主持人把区别讲得更直白：Claude Code、Codex、Cursor 写出来的是代码，这段代码和人写的没有本质差别，可能更好，也可能更差，本质上还是十年前那种代码。而 Jev 是不管写代码的是人还是编程 Agent，都多了一个新零件，能塞进代码里扩展软件的能力。所以它不是用一个更快的程序员去顶替工程师，而是让现有的工程师做出更好、更有意思的东西。

对话后段，这位主持人又给了一个数字来说明为什么光提速不够：大公司里一个 PR（代码合并请求）平均只有十行左右，他说自己在谷歌待过，团队做过这个研究。所以就算 AI 把这十行写得更快，被自动化的也只是软件工作里相对次要的部分，而且这十行往往还来自对客户的某个洞察，软件本身并没有因此长出新能力。他说，在 Jev 出现之前，他都没意识到：不管用多少 AI 编程 Agent，软件其实没变好，写得更快了，甚至可以说更糟，因为监督变少了，往往还更不安全。

另一位主持人问了个怪问题：有了这样的零件，编程 Agent 的价值会不会下降？Diogo 说这更像编程 Agent 的问题。他自己的体验是，这些工具擅长语法，不擅长语义，架构尤其弱，大概处在第 50 百分位；如果你不懂架构，这样够用，有时候速度才是那个要拧的旋钮。

在专访里，他从另一个角度批评了今天的编程 Agent：它们建立在“单个模型”上，被锁在一个模型里，状态只能不断往后追加，所以没法让子任务用更便宜的智能。他设想过另一种做法：给每个子任务一个便宜的模型，用带标签的任务树管理状态，并行的子 Agent 之间共享状态，靠智能去协调，而不是靠简单的锁。他说这方面有很多值得重新想的地方。

### 怎么用才靠谱

**先看 AI 为什么一直进不了软件。** 这是一位主持人的分析。他说，人们不明白 AI 和软件是怎样“擦肩而过”的：就算你想把 AI 嵌进软件，它也不听话，因为软件不吃自然语言。你在 prompt 里写“我要这样的 JSON 输出，这是 schema”，它常常不照办。于是最后只有两条路：要么把输出交给人看，也就是聊天；要么交给另一个大模型，也就是 Agent 的 while 循环，因为自然语言得再喂给下一步。他说自己见过这个过程，像悲伤的五个阶段：先是否认，拼命想让它跑通，再是愤怒，最后接受，算了，交给人或者另一个大模型吧。他说，这是他第一次见到有人说，其实可以把 AI 映射成状态机，而且真能用起来。

把三条路放在一起看，差别在于“谁来做最后那个决定”。

#### 让 AI 进软件的三条路，谁来做最后的决定

1. 客户来信进来
2. AI 读信，写出一段分析（一段自然语言）
3. 人读懂这段话
4. 人自己去系统里点操作

**决定由谁做：**人。AI 只负责说，最后一步始终要人来接。

**再看 Diogo 教的用法：拆成很多小问题。** 专访里他说，写 Jev 的查询，要像写程序一样明确、结构化，让问题尽量字面，因为写程序要的就是能被严格执行。他的例子是拒答：不要问“这里该不该拒绝”，而是拆成许多个独立的问题，每个问题问一种具体情形，各设一个阈值，由你的代码决定最后怎么做。这样做有个好处：发现哪里出错了，就加一个问题、一个阈值，再记成一个测试用例，这个问题就永久解决了，软件不会像塞在 prompt 里的说明那样，随着上下文变长而“腐烂”；他把这叫“没有机器学习的机器学习”。

**最后是他对“可靠”的要求。** 主持人问，可靠性指模型的可用性，还是同样的调用返回同样的结果？Diogo 把它拆成三层：

- **可用性**：能不能正常调用，他称之为正常运行时间或 SLA；
- **确定性**：调用两次是不是逐字返回一样的结果；
- **稳健性**：每次都有相近的智能水平。

他说第三层最接近他要的东西。他的看法是，确定性对单元测试有用，但不是对的北极星；他们测稳健性的办法，是往 prompt 里塞一串无关的随机编号（他在专访里说叫 nonce，访谈里说 UUID），语义上是同一个问题，输出应该相近。他想要的是，每次不必是同一个函数，但每次都得够聪明，让人看了觉得“这个反应合理”，这样开发者才敢围绕它编程。在专访里他还说，可以做出确定性的模型，但那意味着更低的每美元智能。

- **稳健性**结论一致且合理 ✓

这是最理想的情形，但真实系统里很难做到，也没必要做到。

他给可靠性的“最高荣誉”是：人们可以直接针对 Jev 编程，而不用再写示例查询。他还说，每多一个 9 的可靠性都很有价值，哪怕它不是市值上最值钱的部分，因为它会催生新的应用。

他对“什么算靠谱”的要求也比较苛刻。有人问他最喜欢什么用例，他说不确定它们真能用；他要的是能在后台跑、让人放心，不会半夜叫醒人，别人还能在上面搭，也就是“可组合”。他说，AI 圈掉进了一个反模式：只盯着极端案例和演示。专访里他还提过一个设想，并说自己也不确定会怎么走：靠校准加模型级联，很自信就用小模型，中间地带升级到更大的模型，一层层往上。

### 外界怎么看：几个尖锐的质疑

这些都不是 Diogo 说的，是外界的看法，放在这里，是因为它们直接影响你怎么判断 Jev。

**“零幻觉”的意思是“零越界”，不是“零错误”。** 官方博客写“Jev 不会幻觉”。KDnuggets 的评论和 HN 上的讨论都指出：如果你给的选项是账单、技术、销售，它不可能突然答出“法务”，因为这个答案不在选项里；但它仍然可能把该选“技术”的问题选成“账单”。官方自己的措辞其实更克制：类型错误在数学上不可能，这个数字不是实测，是保证。

示意演示 · 概率数字取自 KDnuggets 转引的官方示例，其余为编写的例子

#### “不会幻觉”到底保证了什么

来信：“我昨天升级了，但付费功能还是用不了。”

这可能涉及合同条款，建议转交法务部门。

超出了你定义的选项

自由文本什么都可能说，程序得再去解析、校验，才能知道能不能用。

**“这不就是分类器吗？”** KDnuggets 的作者做过多年分类和语言模型，他说分类、零样本分类、校准概率、用专用小模型省钱，这些都不是新东西；真正新的可能是围绕这类任务重做的架构、训练和产品。Diogo 在访谈里自己就说 Jev“绝对是个分类器”，并不回避。HN 上也有人说，早就用 BERT 做过类似的事。

**数字是自家评测的结果。** 官方的“更快更便宜”来自他们自建的“工作流评测”：参考答案是 GPT-6 Astra 与 Fable 5.1 的平均，题目由自家团队做，官方承认可能有偏差，并说这些倍数是真实场景里偏高端的情形。KDnuggets 还指出，官方报的约 68% 是“与前沿模型答案的一致度”，不是真实准确率；已有的独立小测，比如一个事实核查测试的 96.3%、一个 275 篇文档的分类测试，规模都很小。官方也说，速度数据是从他们西海岸的笔记本上跑出来的，无法证明定价不是补贴，要靠长期证明。

**有没有护城河。** HN 上有一条讨论，认为 OpenAI 很容易跟进：Jev 没有别的护城河，只是没人这样打包过一个模型。也有人反驳，重要的是它把接口做对了，不是护城河。这两种说法都只是网友观点，我没有核实。

对这些质疑，Diogo 的态度是：官方博客写“我们喜欢怀疑者，我们自己也是”，也承认有些说法没法证明；访谈里他也说，自己不知道 Jev 是否已经能满足所有被吹过头的应用，只是团队会为此拼命。

### 两个有争议的立场

**不做拒答。** 专访里，他解释了为什么反对在 API 层做安全对齐：拒答对他来说是一个“类型错误”。在聊天里，你被拒绝，只是烦；但如果模型藏在软件的依赖里，别人不知道里面是什么，它却因为用户发来一条奇怪的信息就随机拒答，软件就会随机崩。他说，安全对齐对聊天产品是合理的，因为那是在按别人（OpenAI、Anthropic）的指令行事，但在 API 层是不能接受的，因为开发者需要围绕它编程。主持人反驳：那要是被用来杀人呢？他说自己当然希望不被用于这类事，也会在别处使劲，但不会在技术这一层加价值观，因为每次让模型去迎合某个奇怪的目标，都在“割裂”它的智能；他认为智能会更像数据库，而不是同事，数据库不该检查用户拿它做什么。这个立场有争议，我只转述，不评判。

**不看公开基准。** 他在专访里说，公开基准很容易被刷，过去每家实验室都有团队专门收集“长得像 MMLU”的数据；长期来看，信任要靠“感觉”，加上把它放进自己的工作流里去测。官方博客也是这么做的：用他们设计的“工作流评测”，而不是通用的排行榜。代价是外界难以独立复核，这正是上面那些质疑的来源。

### 对不同的人意味着什么

**对开发者**：多了一个可以塞进自己代码的零件，不用先训练模型。他的期待是，人们直接针对它编程，而不是不断调 prompt。官方和外部的早期用例包括：Agent 路由（一位开发者报告决策在 145 到 271 毫秒之间）、模型路由、浏览器 Agent 等。

**对 SaaS 公司**：一位主持人说，编程 Agent 出来时，出现过“SaaS 末日”的说法，估值一落千丈；Jev 出来后，每家 SaaS 公司又都说这是最棒的东西。Diogo 说，“SaaS 末日”里最站不住脚的是“软件很便宜也容易复制”：前半句他信，后半句不信，因为软件底下压着很多历史包袱。他反而认为 SaaS 会是这轮 AI 最大的赢家之一：最大、最无聊、最懂用户问题的公司，最清楚哪些工作流该自动化，而且它们的资本投入很大一部分本来就花在触达所有客户上，现在能让软件本身好上一大截，而不只是在产品上加个聊天机器人。他说自己不预测金融市场，讲的是能力层面的判断，还把它叫“反向的 SaaS 末日”。

**对普通用户**：他设想过，多选表单可能会消失，因为它们总是在把软件里已有的自然语言映射成类似 Jev 的输出。他提到 20 世纪 80 年代有个东西叫 4GL，当年也想让人用接近自然语言的方式写程序。他觉得界面可能会彻底改变，不过得让它更便宜、更快。他还说，智能可能像正则表达式那样，融进背景里，不再引人注意。

**对系统层面的人**：他说，当有了大量不同成本、不同速度的智能，最“系统派”的人会自己做取舍，Jev 对他们来说会“聪明一千倍”，用不上，他们只想要一个近似的猜测，乐观地把请求路由到各处。他说好消息是，这意味着我们又有机会重建系统：有了新的基础零件，就像互联网和客户端服务器时代那样，周期性地这么干。一位主持人还提到，仅网络安全的问题，就可能得重建几乎所有系统，至少关键基础设施肯定要。

**对工作岗位**：一位主持人说，他最喜欢 TypeSafe 的一句话是“我们做产品，不造神”（build prod, not God）：别的大实验室负责人就算心里高兴，也会藏起来，而 TypeSafe 的态度是：我们要造一个好得多的世界，岗位不会变少，还会更多、更好。Diogo 表示认同，说自己不认同悲观叙事，认为那源于大家信了“一个大脑统治一切”的单一模型迷魂汤。

### 还没有答案的地方

Diogo 划了自己的边界：先自动化容易的活，再碰难的。一位主持人指出，这到底能做到多深还是很开放的问题，比如状态一致性、持久性，或需要强保证的系统层面；Diogo 同意，并说能确定的是，分析日志、分析邮件、提供界面、和人对话这些一定会改变。至于更远的，他说久而久之它可能变成智能数据库，甚至空中交通管制系统，对话里有人说这“有点吓人”。他还说，如果要给它接上资源和权限，就需要保证，至少是统计意义上的保证，这一点他们的模型短期内做不到，除非有人写软件来做。

他也提到方向上的几点：概率编程有很长的历史，大约在 20 世纪 70 年代没落，他觉得这次也会有起伏；他自己的标签是“极度务实”，并不喜欢受生物启发的东西，说那从来没成功过；他说自己为世界兴奋，而不是为自己去编写这套东西，因为听起来太复杂了。

### 这个人是谁

他的路径有点野。数学竞赛选手出身，但说自己其实从没真正喜欢过数学，觉得计算机科学“像数学，但酷、有用、有趣”，更认同自己是计算机科学家，而不是 AI 研究员。他靠赢下一场 Kaggle 比赛入行，那次靠的不是高深数学，而是疯狂自动化；后来还得去 NeurIPS 演讲，他说这本是荣誉，自己却讨厌，只想埋头干活。之后他和 Jeremy Howard 创过业，在 Google Brain 待过，又在 OpenAI 工作。官方博客说，TypeSafe 在隐身状态下做了两年，才发布 Jev。

访谈结尾，他把自己想要的东西归结成四个字：do what I mean。他说，那是世界的顺滑，所有东西像齿轮一样咬合；想象所有技术都照你的意思办，这不是科幻。

a16z Interview · TypeSafe · Jev

## TypeSafe 创始人讲 Jev：Jev 到底是什么？AI 聪明得离谱，自动化到底去哪了？

AI 聪明得离谱，软件却没怎么变。一位前 OpenAI 研究员认为，问题出在训练目标上，于是做了一个不聊天、只在预设选项里给出带把握判断的模型。

一页读懂：问题 → 他的诊断 → Jev 是什么 → 怎么用 → 外界怎么看

访谈的起点是一句反问：**自动化到底都去哪了？**除了聊天和编程，AI 在企业里几乎没帮上忙。他给了三个依据：

95%→50%客服号称答了 95% 的来电，多是重置密码；按问题独特程度算约 50%
≈10 行大公司一个 PR 平均十行左右，AI 写得再快，自动化的也只是次要部分
<1%他估计模型完成有经济价值工作的比例，大约还是零，不到 1%

核心机制

**Jev 是塞进代码里的零件，不是写代码的工具。**官方的定义是“前沿智能的函数调用”：非结构化的状态进去，类型化的概率决策出来。区别在于：让 AI 进软件，最后那个决定由谁来做。

**聊天**AI 写一段话，人读懂后自己去操作。决定在人手里。
**Agent 循环**AI 的文字交给另一个模型解读，一圈圈转。决定在一串模型里。
**状态机（Jev）**模型在预设选项里选一个并给出把握，软件自己往下走。

1. *STATE*一封客户来信
2. *CHOICES*退款 / 技术故障 / 咨询
3. *OUTPUT*选中一项，附置信度
4. *CODE*够把握就自动处理，不够转人工

所以它和 Claude Code、Codex 不在一层：编程 Agent 让写软件更快，写出来的仍是老样子的代码；Jev 让软件本身多一种带着把握做选择的能力。官方给的速度是 70 到 500 毫秒，输入每百万 token 0.042 美元。

**他的诊断：训练时用什么当目标，模型就会长成什么样。**聊天模型为让人满意而训练，概率变得不诚实，不适合在软件里做决定。

**RLHF**优化：让人类评分者满意代价：迎合、失去校准
**RLVR**优化：能被程序验证的结果代价：能力参差，难与软件集成
**RLCD**优化：带诚实概率的决策（Jev）代价：放弃自由文本，能力更窄

**怎么用才靠谱：**别问一个大问题，拆开问。

1. 把一个大判断拆成许多独立的小问题，每个只问一种具体情形。
2. 每个小问题各设一个阈值，最后怎么办由你的代码决定。
3. 出错时加一个问题、一个阈值，再记成测试用例，这类错误就被永久固定，不像提示词会随上下文“腐烂”。

可用性：能不能调用
确定性：逐字相同
稳健性：每次都够聪明（他要的是这个）

**外界质疑（不是他的说法）**

- “零幻觉”等于零越界：不会答出选项外的东西，但仍可能选错。
- 分类、零样本分类都不是新东西，新的可能是架构和产品。
- 官方数字来自自家评测；外界指出 68% 是与前沿模型答案的一致度，不是准确率。
- 有人认为 OpenAI 很容易跟进，护城河存疑。

还没答案的是需要强保证的系统场景：状态一致性、持久性、给它接上资源和权限。他自己说，这些短期内做不到；他想要的终点是 do what I mean。
