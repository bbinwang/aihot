### 模型、编译器和客户端分别负责什么？

在原生组件路径中，客户端的工作还分成两部分：运行时执行逻辑并产生更新操作，渲染器按这些操作绘制组件。沿着同一份月费估算，可以把模型、编译器与客户端的分工逐步接起来。

#### 模型：用 DIL 描述内容、组件和逻辑

大模型在生成回复时，使用的并不是纯文本，也不是传统的 JSON 结构树，而是一种名为 **DIL** 的专用语言。它由三部分融合而成：

- **普通 Markdown**：用于书写段落文字与排版标题；
- **类似 JSX 的组件标签**：用于声明布局容器与功能组件（如 `<box>`、`<slider>`、`<title>`）；
- **内联 JavaScript（以 `{@body ...}` 标识）**：用于声明内部响应式状态（State）与推导逻辑。

观察一个典型的教学测算示例（注：示例中 $29/席位/月为用于演示公式逻辑的教学数据，非真实套餐定价）：

```dil
### Team plan estimate
Drag the slider to see the **monthly price** for your team.
{@body const [seats,setSeats] = DIL.useState(8)}
{@body const price = seats*29}
<box border padding={3} gap={2}>
  <slider min={1} max={50} value={seats} onChange={setSeats}/>
  <title size="xl">${price}/mo</title>
</box>
```

在这个片段里，模型通过 `DIL.useState(8)` 定义了默认席位为 8，通过普通 JavaScript 表达式计算总价，再将状态与滑块组件绑定。这条推文把主路径概括为“模型从不写原始代码”，这并不准确——**模型确实在直接编写 JavaScript 逻辑**，只不过它被放在专用标记语言中。

#### 编译器：把描述转换成可运行程序与数据

客户端浏览器**不会按原样直接执行**模型生成的原始 DIL 字符串。OpenAI 的后端服务器会处理模型输出流，将其动态编译为一个独立的 JavaScript 执行函数和一份 JSON 常量配置表（在会话元数据中标记为 `model_dil_v2`）。回复中的普通 Markdown（标题、段落、粗体）也会被编译进同一棵组件树（如转化为 `title`、带 `bold` 的 `text`），文字则抽离移入 `constants` 常量表。

服务端编译器主要完成五项关键加工：

- **函数标准化**：将所有 XML 风格的标签转译为 `__dil.jsx(...)` 函数调用，客户端不再需要 DIL 语法解析器。
- **表达式容错**：编译器用 `__dilSafe` 包装表达式，出错时返回备用值，帮助隔离局部错误。这能减少一处异常对整份回答的影响，但不检查公式是否正确。
- **文本抽离为常量表**：静态文字被移入名为 `constants` 的哈希字典，例如 `{"0": "Team plan estimate", "4": "$"}`。这样在后续打字流中，文本的增多只会修改 JSON 字典，而不需要修改 JavaScript 代码本身。
- **为状态加入稳定键**：为每一个状态钩子注入稳定键（如 `{ key: "seats" }`），确保界面后续重新编译时，用户拉过的滑块位置不会被冲刷回初始值。
- **白名单校验与自动修复**：依据设计系统字典（Catalog）严格过滤非法属性（例如发现模型写了未定义的 `fill` 属性或格式错误的数值，直接在编译期剔除并打上诊断标记）。

#### 客户端：隔离运行逻辑，把结果显示成原生界面

##### 在沙箱里执行逻辑、保存状态

大模型生成的代码本质上是不受信任的外部输入。如果直接在宿主页面运行，极易带来 XSS 攻击或数据泄露隐患。

ChatGPT 在浏览器端采用了一套分层隔离方案：

- 页面预先加载一个隐藏的沙箱 iframe（`runner.html`），并赋予严格的 CSP（内容安全策略：`default-src 'none'`），限制资源访问。
- 该 iframe 随即启动一个专属的 **Web Worker**。
- **限制可用能力**：Worker 在执行程序前移除模型代码可访问的网络、定时器、消息传递和动态代码执行能力，并冻结剩余全局对象。运行时自身仍通过受控的求值入口执行编译程序。
- **内置微型调和器（Mini Reconciler）**：Worker 内部运行着一个类似 React 的调和器。它执行组件逻辑，比较新的组件树与上一次组件树，计算需要更新的操作，并序列化为底层的二进制 UI 操作指令（如 `CREATE #9 slider`）。
- **函数不离开沙箱**：组件绑定的事件处理函数（如 `onChange`）绝不向主页面传输，主页面只能拿到一个标识符（如 `fn#1`）。
- **看门狗机制（Watchdog）**：若某段逻辑陷入死循环或执行超时，看门狗会强行杀掉并重启 Worker。
