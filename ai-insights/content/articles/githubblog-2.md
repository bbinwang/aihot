我们开发者的工作正在发生变化。短短几年间，我们从亲手编写每一行代码，到与 AI 助手协作，再到编排成群的 Agent。但目标从未改变：交付已完成的软件工作。一个功能、一个 bug 修复、一个安全修复。真正重要的产出是完成的工作，而不是更多的代码。

今天，在 [GitHub Universe](https://github.com/events/universe/recap?utm_source=gh-universe-blog-k2k&utm_medium=blog&utm_campaign=universe-2026) 上，我们分享了我们对 GitHub 的愿景——成为全球最全面的软件交付系统。我们介绍了将这一愿景变为现实的产品，并展示了我们如何重建其底层基础设施。

### 我们的愿景：从想法到完成的软件

[SDLC 不再是一条从规划到编码、测试再到部署的线性路径](https://commandline.microsoft.com/new-agentic-software-delivery-primitives/)。一次代码变更、同事的一个请求，或一项生产环境指标，都可能触发系统中任何位置的工作。我们大多数人(以及我们的 Agent)会根据手头的任务在不同阶段之间来回切换。开发者设定方向、做出决策，并对最终交付的内容负责。Agent 负责实现并验证变更。而一切都汇入又流出一个持续学习的机制，让下一个周期变得更好。

这套 agentic 软件交付系统致力于解决三件事：

- **Velocity(速度)：** 以尽可能快速、高效且具成本效益的方式，从想法直达完成的软件
- **Intelligence(智能)：** 将整个平台的上下文与持续学习引擎相结合，让系统在你使用的过程中不断进步
- **Quality(质量)：** 让完成的工作默认安全，并在交付之前捕获 bug

GitHub 是为开发者及其 Agent 而构建的。我们也将开放底层 primitives,让你能够构建自己的定制化解决方案。对工作、工具和成本的控制权，始终掌握在你手中。

### 推动工作向前的新功能与新产品

今天在 Universe 上，我们现场演示了部分最新产品与功能，首先从 GitHub Copilot app 开始。

#### GitHub Copilot app:从 issue 到 merge,尽在一个 app 中

[GitHub Copilot app](https://github.com/features/ai/github-app?utm_source=gh-universe-blog-app-feature&utm_medium=blog&utm_campaign=universe-2026) 从零开始专为 agentic 软件交付而设计。它将你的 Agent 和工具跨项目连接起来，因此你可以指挥工作，而无需亲自完成每一次交接。它的用途也远不止生成代码：你可以在一个 agent-first 的界面中编写 spec、展示设计讨论或分析遥测数据。

#### Copilot Fusion: 多模型编排的巅峰之作

不同的任务需要不同的模型。开发者不应该为了以合适的价格获得合适的结果而自行管理每一次模型选择。[Copilot Fusion](https://docs.github.com/copilot/concepts/models/copilot-fusion?utm_source=gh-universe-blog-fusion-docs&utm_medium=blog&utm_campaign=universe-2026) 会评估任务在推理、代码生成、调试和 tool use 方面的需求，然后决定如何跨一个或多个模型来执行。在 Artificial Analysis Coding Agent Index 中，Fusion Max 的得分与 Opus 5.5 Max 相差不到两分，而成本只有一半，每个任务的耗时减少 40%。

#### Copilot projects: 给 Copilot 一个目标

从今天起，GitHub Copilot app 原生支持 [Copilot projects](https://docs.github.com/copilot/how-tos/github-copilot-app/working-with-projects?utm_source=gh-universe-blog-projects-docs&utm_medium=blog&utm_campaign=universe-2026),让你可以在完全托管的并行 session 中跨多个 repo 执行 agent 工作。你只需在一个地方就能跟踪进度、做出决策并指示接下来要做什么。这意味着你可以花更少的时间管理执行，把更多时间用于决定什么值得构建。

#### Session continuity: 跨端持续工作

当你切换设备或工具时，工作不应该从头开始。[Session continuity](https://docs.github.com/copilot/how-tos/copilot-on-github/use-copilot-agents/manage-and-track-agents?utm_source=gh-universe-blog-session-continuity-docs&utm_medium=blog&utm_campaign=universe-2026#continue-a-session-from-another-client) 让你可以在 GitHub app、VS Code、CLI 和网页上启动并跟踪同一个云端 agent session。在每日站会时从手机上启动，在工位上从 VS Code 中引导方向，午餐时在 github.com 上查看进展。agent 会在云端持续工作。支撑这一切的多模型 harness 强大、快速且高效。

#### Copilot automations: 从结果中学习

[Copilot automations](https://docs.github.com/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/about-automations?utm_source=gh-universe-blog-automations-docs&utm_medium=blog&utm_campaign=universe-2026) 让你可以在 repo 内创建由 AI 驱动的工作流。它们在云端运行，你可以手动触发，也可以设置为由事件响应或按计划运行。这样你就能协调 agent 来处理 issue 分类和 code review 等任务。现在，automations 还可以从执行结果中学习，并提出改进建议供你审核和批准。这就是学习引擎的实际应用：利用已完成工作的结果，让下一次运行做得更好。

#### Copilot code review Max: 更深入地审视交付的代码

代码越多，意味着 pull request 越多，对 review 的需求也越大。只有在能够保持交付质量的前提下，提升速度才有意义。[Copilot code review](https://docs.github.com/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/code-review?utm_source=gh-universe-blog-code-review-overview-docs&utm_medium=blog&utm_campaign=universe-2026) 能够发现开发者需要捕捉的、有意义且可操作的 bug。今天，我们推出了 Copilot code review Max,它在 ReviewBench 上针对高严重性问题取得了最高的 F1 分数。Lite 和 Balanced 保持日常 review 的快速；而新的 Max 则在变更需要时提供更深入的分析。

#### 无需单独的企业订阅即可使用 Copilot 功能

从今天起，GitHub Enterprise 客户无需购买单独的订阅即可使用所有 Copilot 功能，包括 GitHub Copilot app、code review、automations 等。你只需为实际使用的 AI credits 付费。

现在可以通过 [GitHub Sales](https://github.com/enterprise/contact?utm_source=gh-universe-blog-contact-sales-form&utm_medium=blog&utm_campaign=universe-2026) 获取，自助服务即将推出。现有的 Copilot Business 和 Copilot Enterprise 客户可以保留当前计划，或在准备好后迁移过来。GitHub 也始终保持开放和可扩展。你可以继续使用团队依赖的工具，包括 Cloudflare、Datadog、Figma 等。

### 我们持续的基础设施投资

这一切都依赖于一个快速、可靠、为扩展而构建的基础。Agent 正在改变软件开发的规模与形态。增加容量固然重要,但仅靠容量是不够的。我们还必须改变架构。

今年以来,我们已新增:

- 400 万个 CPU 核心
- 160 PB 高速存储
- 50 Tb/s 网络容量

我们还在迁移[至 Azure 的多区域部署](https://github.blog/engineering/architecture-optimization/the-bridge-to-agent-scale-git-infrastructure/?utm_source=gh-universe-blog-git-infra-blog&utm_medium=blog&utm_campaign=universe-2026),同时持续为来自世界各地开发者的高额流量提供服务。我们预计将于明年初完成迁移。这些投资为我们提供了更大的增长空间。下一步是构建能够胜任这项工作的系统。

随着 GitHub 上活动的增长,我们多年来一直在扩展 Git。Agentic 时代对吞吐量和可靠性提出了截然不同的上限要求。我们的新 [Git 架构](https://github.blog/engineering/architecture-optimization/building-git-infrastructure-for-agent-scale-development/?utm_source=gh-universe-blog-git-architecture-blog-1&utm_medium=blog&utm_campaign=universe-2026)遵循三大原则:简化原语、将存储与计算解耦、最大限度减少协调。

Git 只是我们在平台扩展方面所做工作的一个例子。我们在 GitHub 的 AI gateway、harness 等诸多方面都开展了大量工作。

### 超越最初的 1%

我们的工作正在发生变化,但开发者比以往任何时候都更加重要。我认为,迄今为止我们编写的所有软件,将只占未来五年所写软件的不到 1%。机遇不仅在于产出更多代码,更在于解决我们以前无法解决的问题。

这就是为什么我们正在连接完整的软件交付系统,为开发者提供与 Agent 协作的更好方式,并为未来演进基础设施。我们正在 GitHub 上做这一切,在这里我们可以共同构建。
